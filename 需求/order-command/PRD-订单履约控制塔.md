# 订单履约控制塔 — 前端开发 PRD

## 1. 产品概述

**产品名称**：订单履约控制塔  
**产品定位**：面向企业运营团队的 Agent Skill应用，通过 AI 自动分析销售订单履约状态，识别交付卡点，生成可执行任务。  
**目标用户**：运营人员（如「Hi·金星米」角色）  
**核心场景**：用户选中若干销售订单，向 AI 发起分析请求，AI 调用企业内部系统（销售系统、ERP、采购系统等）数据进行综合分析，输出问题看板与待办任务清单，并跟踪任务执行。

### 1.1 核心概念

| 概念 | 说明 |
|------|------|
| **分析任务** | 用户每次选中订单并向 AI 发起的一次分析请求，产生一份独立的分析报告 |
| **Sub-Agent** | 用户向 AI 提问时可选择的专业分析维度/角色（如「交付卡点分析」「库存风险分析」等） |
| **问题卡片** | 看板分析中以物料行为粒度拆分出的具体问题项，属于某一个问题分类泳道 |
| **Agent 任务** | 由 AI 自动执行的任务（如确认发货计划、生成 PDF） |
| **决策任务** | 需要人工审批/决策的任务（如确认运输车辆、签署通知单） |
| **手工任务** | 需要人工手动操作的任务（如核对出库单、更新物流编号） |

### 1.2 系统架构（四大菜单）

```
┌─────────────────────────────────────────────────────────────┐
│  首页  |  历史分析  |  任务列表(42)  |  系统设置              │
└─────────────────────────────────────────────────────────────┘
         ↑                      ↑
    全局菜单                全局菜单
    （每次分析任务          （汇总所有分析任务
     都会在此记录）          产生的待办任务）
```

- **首页**：核心分析工作台，发起 AI 分析、查看看板结果
- **历史分析**：全局查询入口，查看所有历史分析任务的列表与统计
- **任务列表**：全局任务中心，汇总所有分析任务产生的待办执行任务
- **系统设置**：后续单独开发，目前仅占位

## 2. 业务流程（主线流程）

```
Step 1: 进入首页
    │
Step 2: 在右侧销售订单列表中，选中若干合同
    │  ──▶ 点击「添加至对话」，选中的合同进入中央对话区
    │
Step 3: 选择 Sub-Agent，输入分析指令
    │  例："帮我分析这几个合同当前的交付卡点是什么"
    │
Step 4: AI 开始分析
    │  ──▶ 调用接口查询销售系统、ERP、采购系统等数据
    │  ──▶ 页面可展示分析进度（进度条/Thinking 状态）
    │
Step 5: 分析完成，自动跳转至「看板分析」页面
    │  ──▶ 左侧：展示选中的销售订单及发货比例
    │  ──▶ 中间：问题分类泳道，每个卡片是一个物料行级别的问题
    │  ──▶ 右侧：点击卡片后展示该物料的交付路径、风险分析与建议
    │
Step 6: 用户在左侧选中若干合同，点击「生成待办清单」
    │  ──▶ AI 结合问题类型，给每个合同解析出待办清单
    │  ──▶ 切换至「合同待办清单」子视图查看
    │
Step 7: 点击待办清单中的某个任务
    └──▶ 进入任务详情页（Agent / 决策 / 手工）
```

## 5. 页面详细说明

### 5.1 首页（`index.html`）

**定位**：整个系统的核心分析工作台，用户在此发起每一次 AI 分析请求。

**布局**：三栏布局
- **左侧边栏**（可折叠，44px~224px）：近期历史分析任务列表，支持新建会话
  - 折叠态：仅显示图标 + 首字母
  - 展开态：显示完整任务标题 + 日期分组
  - 顶部「新建分析」按钮
- **中央区域**：AI 对话交互区
  - 顶部：已添加至对话的合同列表（横向标签形式，可删除）
  - 中部：对话消息流（用户提问 / AI 回复 / 分析进度提示）
  - 底部：输入框 + Sub-Agent 选择器 + 发送按钮
- **右侧面板**（300px）：企业销售订单列表
  - 顶部：搜索/筛选栏
  - 中部：订单表格/卡片列表，支持多选（checkbox）
  - 每行展示：合同号、客户名称、订单金额、交付状态、发货比例等
  - 底部：「添加至对话」按钮（选中后可用）

**关键交互**：

| 元素 | 交互 | 说明/跳转 |
|------|------|----------|
| 右侧订单列表多选 | checkbox | 选中后激活「添加至对话」按钮 |
| 「添加至对话」按钮 | 点击 | 选中的合同以标签形式出现在中央对话区顶部 |
| 对话区合同标签 | 点击 × | 从当前对话中移除该合同 |
| Sub-Agent 选择器 | 下拉选择 | 选择分析维度（如交付卡点分析、库存风险分析等） |
| 输入框 + 发送 | 点击/回车 | 向 AI 发送分析指令 |
| AI 分析中 | 自动 | 显示 Thinking/分析进度状态，调用后端接口 |
| 分析完成 | 自动跳转 | 跳转至 `analysis-result.html`（看板分析子视图） |
| 左侧历史任务点击 | 点击 | 加载该历史分析的上下文，可继续对话或查看结果 |
| 左侧「新建分析」 | 点击 | 清空当前对话，开始新的分析会话 |

**数据流**：
```
用户选中订单 ──▶ 添加至对话 ──▶ 选择 Sub-Agent + 输入指令 ──▶ 发送
                                                        │
                                                        ▼
                              ┌─────────────────────────────────────┐
                              │ 后端：AI 分析引擎                      │
                              │  ──▶ 调用销售系统接口查询订单状态        │
                              │  ──▶ 调用 ERP 接口查询库存/生产进度      │
                              │  ──▶ 调用采购系统接口查询物料到货情况     │
                              │  ──▶ 综合分析生成问题看板数据            │
                              └─────────────────────────────────────┘
                                                        │
                                                        ▼
                                              返回分析结果
                                                        │
                                                        ▼
                                            跳转看板分析页面
```

### 5.2 看板分析（`analysis-result.html`）

**定位**：单次 AI 分析完成后的结果展示页。包含两个子视图：「看板分析」和「合同待办清单」。

> **注意**：该页面的「合同待办清单」仅展示**当前这次分析所产生的任务**，是全局「任务列表」的一个子集。全局任务列表汇总了所有分析任务的待办。

#### 子视图一：看板分析（默认）

**布局**：三栏布局
- **左侧面板**（260px）：合同列表
  - 展示本次分析涉及的所有销售订单
  - 每行显示：合同号、客户名称、发货比例（进度条）
  - 支持多选（checkbox），用于后续「生成待办清单」
  - 面板底部：「生成待办清单」按钮（选中合同后激活）
- **中央区域**：问题分类看板
  - **纵向泳道**：每个泳道是一个问题分类（如「库存不足」「运输延期」「质检异常」「供应商延迟」等）
  - **卡片**：泳道内每张卡片对应一个**物料行级别**的问题
    - 卡片内容：物料编码、物料名称、问题简述、严重程度标识
  - 卡片支持拖拽（可选）
- **右侧面板**（300px）：问题详情
  - 默认态：提示「点击左侧卡片查看详情」
  - 选中卡片后展示：
    - 物料基本信息（编码、名称、规格、数量）
    - **交付路径**：从采购/生产 → 入库 → 出库 → 运输 → 交付的完整链路状态
    - **风险分析**：AI 识别的风险点及原因
    - **建议措施**：AI 给出的处理建议
    - 相关系统数据快照（ERP 库存、采购订单状态等）

**关键交互**：

| 元素 | 交互 | 说明 |
|------|------|------|
| 左侧合同列表多选 | checkbox | 选中后激活底部「生成待办清单」按钮 |
| 「生成待办清单」按钮 | 点击 | AI 结合选中合同的问题类型，解析出待办清单，切换至「合同待办清单」子视图 |
| 中间看板卡片 | 点击 | 右侧面板加载该物料的问题详情 |
| 中间看板卡片 | 悬停 | 显示卡片 tooltip（问题概要） |
| 子导航「合同待办清单」 | 点击 | 切换至待办清单子视图 |

**布局**：单页内容区

- 子导航：

**关键交互**：

| 元素 | 交互 | 说明/跳转 |

**定位**：全局菜单，汇总**所有分析任务**所产生的待办执行任务。

> **与看板分析待办清单的区别**：
> - 看板分析中的「合同待办清单」= 单次分析产生的任务子集

**布局**：左侧筛选边栏 + 右侧内容区
- **左侧边栏**（240px）：多维筛选面板
  - 任务类型（Agent / 决策 / 手工）

  - 负责人

  - 业务类型（发货 / 入库 / 合同确认 / 异常处理）
- **右侧内容区**：
  - 子导航：全部任务 / 发货任务 / 入库任务 / 合同确认 / 异常处理（快速筛选）
  - 统计卡片：全部 / 进行中 / 逾期 / 待开始 / 已完成（点击筛选）
  - 任务数据表格

**关键交互**：

## 6. 数据模型关系

```
┌─────────────────┐         ┌─────────────────┐         ┌─────────────────┐
│   分析任务       │ 1    N  │   问题卡片       │ 1    N  │   待办任务       │
│ (analysis_task) │────────▶│ (issue_card)    │────────▶│ (todo_task)     │
└─────────────────┘         └─────────────────┘         └─────────────────┘
        │                           │                           │
        │ N                      N  │                           │ N
        ▼                           ▼                           ▼
┌─────────────────┐         ┌─────────────────┐         ┌─────────────────┐
│   销售订单       │         │   物料行        │         │   任务类型       │
│ (sales_order)   │         │ (material_line) │         │ (agent/decision/│
└─────────────────┘         └─────────────────┘         │  manual)        │
                                                        └─────────────────┘
```

**说明**：
- 一次「分析任务」关联 N 个「销售订单」
- 一个「分析任务」产生 N 个「问题卡片」（按物料行拆分）
- 一张「问题卡片」可产生 N 个「待办任务」（一个物料问题可能需要多个任务来解决）
- 所有「待办任务」汇总到「任务列表」全局菜单

## 11. 技术方案

### 11.1 总体架构

本系统采用**前后端分离 + Skill引擎驱动**的架构。前端页面负责 UI 展示与用户交互，所有 AI 对话能力、Skill 调度、Sub-Agent 编排、数据分析均依托 `claw-code` Skill框架实现。

│  │          │  │result.html   │  │analysis.html │  │task-*.html          │ │

│       │               │                  │                      │           │

### 11.2 claw-code 框架核心组件映射

| 框架组件 (crate) | 对应业务角色 | 在本系统中的应用 |
|------------------|-------------|-----------------|
| `api` | LLM 通信层 | 与 Anthropic/OpenAI 等模型提供商通信，流式接收分析结果 |
| `runtime` | 会话/对话编排引擎 | 管理每次分析任务的 Session 和 Conversation 生命周期 |
| `runtime::conversation` | 对话流编排 | 处理用户提问 → AI 思考 → Tool 调用 → 结果汇总 → 输出看板的完整循环 |
| `runtime::session` | 会话状态管理 | 首页左侧历史分析列表的数据源，支持会话恢复与复用 |
| `runtime::task_registry` | 子任务生命周期 | 管理看板分析问题卡片和待办任务的创建/运行/完成状态 |
| `commands` | Skill/Agent 调度 | 定义和调用 Sub-Agent（交付卡点分析、库存风险分析等） |
| `plugins` | 扩展系统 | 注册企业系统接入插件（销售系统、ERP、采购系统） |
| `tools` | 工具集 | 具体的企业系统数据查询工具（查询订单状态、库存、采购到货等） |
| `runtime::mcp_*` | MCP 协议 | 通过 MCP (Model Context Protocol) 与外部数据服务通信 |

### 11.4 对话流与数据分析实现

#### 11.4.1 对话流编排（依托 runtime::conversation）

前端右侧对话框的所有 AI 对话，均通过 claw-code 的 `ConversationRuntime` 编排：

```
用户发送分析请求
    │
    ▼
┌─────────────────────────────────────────────┐
│ 1. ApiClient.stream(request)                │
│    - 组装 system prompt（Skill prompt）      │
│    - 组装 messages（历史对话 + 当前提问）     │
│    - 发送给 LLM                               │
└─────────────────────────────────────────────┘
    │
    ▼ 流式返回 AssistantEvent
┌─────────────────────────────────────────────┐
│ 2. 处理 Thinking 事件                         │
│    - 前端展示 "AI 分析中..." 进度提示          │
│    - 可展示 Thinking 内容（推理过程）           │
└─────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────┐
│ 3. 处理 ToolUse 事件                          │
│    - LLM 决定调用 tool（如 query_erp_inventory）│
│    - ToolExecutor.execute() 执行工具          │
│    - 结果返回给 LLM 继续推理                   │
└─────────────────────────────────────────────┘
    │
    ▼（可能多轮 ToolUse）
┌─────────────────────────────────────────────┐
│ 4. 处理 TextDelta 事件                        │
│    - LLM 输出分析结论的文本片段                 │
│    - 前端流式展示在对话框中                     │
└─────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────┐
│ 5. MessageStop + 结构化数据推送                │
│    - 对话结束                                  │
│    - 后端将分析结果（问题看板数据）写入数据库     │
│    - 推送消息给前端：分析完成，跳转看板分析       │
└─────────────────────────────────────────────┘
```

### 11.5 任务生命周期管理（依托 runtime::task_registry）

看板分析中的问题卡片和待办任务，统一依托 claw-code 的 `TaskRegistry` 进行生命周期管理。

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   Created   │────▶│   Running   │────▶│   Blocked   │────▶│  Completed  │     │   Failed    │
│   (创建)     │     │   (运行中)   │     │   (阻塞)     │     │   (已完成)   │     │   (失败)     │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
       ▲                   │                   │                    │
       │                   │                   │                    │
       │                   ▼                   ▼                    │
       │            AI 分析中...        等待人工干预                 │
       │            Tool 调用中...      (决策任务)                   │
       │                                                            │
       └────────────────────────────────────────────────────────────┘
                           重新执行 / 恢复
```

**状态映射**：

| TaskRegistry 状态 | 业务含义 | 前端展示 |
|-------------------|----------|----------|
| `Created` | 任务刚创建 | 待开始 |
| `Running` | AI 正在分析或 Agent 正在执行 | 进行中 / AI分析中 |
| `Blocked` | 等待人工决策/操作 | 待处理 / 需决策 |
| `Completed` | 任务完成 | 已完成 |
| `Failed` | 执行失败 | 失败 / 异常 |
| `Stopped` | 用户手动停止 | 已终止 |

### 11.6 前端与框架通信协议

#### 11.6.1 WebSocket 长连接（对话场景）

首页 AI 对话框采用 WebSocket 长连接，与 claw-code 的 ConversationRuntime 保持实时通信：

```typescript
// 前端 → 后端
interface ChatRequest {
  session_id: string;          // 分析任务会话 ID
  skill_id: string;            // 选中的 Skill/Sub-Agent
  contract_ids: string[];      // 已添加至对话的合同列表
  message: string;             // 用户输入的指令
}

// 后端 → 前端（流式推送）
interface ChatEvent {
  type: 'thinking' | 'tool_use' | 'text_delta' | 'message_stop' | 'error';
  data: {
    thinking?: string;         // AI 思考内容（可选展示）
    tool_name?: string;        // 正在调用的工具名
    text?: string;             // 文本片段
    result?: AnalysisResult;   // 分析完成后的结构化数据
    error?: string;            // 错误信息
  };
}

interface AnalysisResult {
  task_id: string;
  contracts: ContractSummary[];
  issue_board: {
    lanes: IssueLane[];        // 问题分类泳道
  };
  todo_list?: TodoItem[];     // 待办清单（如用户已触发生成）
}
```

#### 11.6.2 HTTP API（数据查询场景）

看板分析、历史分析、任务列表等页面的数据查询，通过常规 HTTP API：

```
GET  /api/analysis/{task_id}           # 获取单次分析结果
GET  /api/analysis/history             # 获取历史分析列表
GET  /api/tasks                        # 获取任务列表（支持筛选参数）
GET  /api/tasks/{task_id}              # 获取任务详情
POST /api/tasks/{task_id}/action       # 执行任务操作（执行/审批/驳回等）
GET  /api/contracts                    # 获取销售订单列表
GET  /api/contracts/{id}/todos         # 获取某合同的全部待办
```

### 11.7 开发约定

#### 11.7.1 Skill/Agent 开发规范

1. **命名规范**：Skill 和 Agent 名称使用 `kebab-case`，如 `delivery-blocker-analysis`
2. **目录位置**：优先放在项目根目录 `.claw/skills/` 和 `.claw/agents/` 下
3. **Prompt 规范**：每个 Skill 的 `skill.md` 必须包含明确的输入格式和输出格式要求
4. **Tool 权限**：企业系统查询工具统一使用 `read-only` 权限，写操作需人工确认

#### 11.7.2 前后端接口约定

1. **会话标识**：每次首页新建分析生成唯一的 `session_id`（对应 claw-code Session）
2. **任务标识**：AI 分析完成生成的看板数据对应唯一的 `task_id`（对应 claw-code TaskRegistry）
3. **状态同步**：TaskRegistry 状态变更时，后端主动推送给前端（WebSocket / SSE）
4. **错误处理**：框架层错误（Tool 调用失败、LLM 超时等）统一包装为业务错误码返回前端

#### 11.7.3 与现有原型页面的衔接

现有原型 HTML 文件（`index.html`、`analysis-result.html` 等）为纯前端静态页面，开发时需要：

1. 将静态数据替换为 API 调用
2. AI 对话区接入 WebSocket 流式输出
3. 看板分析页的数据通过 `/api/analysis/{task_id}` 获取
4. 保留现有 UI 样式和布局，仅改造数据层和交互层
